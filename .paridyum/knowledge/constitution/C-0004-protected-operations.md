# Constitution C-0004 — Protected operations

Three categories of action are constrained regardless of who or what initiates them.
The constraint is not a matter of trust — it is that some mistakes have no undo, and
an agent working at speed has no natural pause before them.

## The decision model

| Decision | Meaning | Applies to |
| -------- | ------- | ---------- |
| **deny** | Never legitimate. The tool call fails. | history rewrites on shared branches, editing generated code, overwriting locked artifacts |
| **ask**  | Legitimate sometimes; a human must see the exact command first. An agent cannot self-approve. | infrastructure mutation, deletes, credential operations, governance edits |

Most entries are **ask**, deliberately. A guard that denies everything dangerous is
disabled within a week, and a disabled guard protects nothing. Escalation preserves
the check while keeping the work possible.

## 1. Irreversible operations — ask

- `terraform apply`, `terraform destroy`
- `kubectl delete`, and any command targeting a production context
- `helm upgrade`, `helm uninstall`, `helm rollback`
- database migrations (`sqlx migrate run/revert`, `alembic`, `diesel`)
- `git push --force` to any branch, `git reset --hard`
- recursive delete against an absolute path, `$HOME`, or a glob
- secret and credential operations (`gh secret set`, key generation)
- `gh repo delete`, destructive `gh api -X DELETE`

Recursive deletes of relative build directories (`rm -rf ./target`,
`rm -rf node_modules`) are **not** escalated. Escalating routine commands trains the
habit of approving without reading, which is how a real one gets waved through.

## 2. History — deny

```
LAW: history is sacred.
```

Force-pushing to `main`, `git filter-branch`, `git filter-repo`, and BFG are denied
outright. If a commit must be undone, revert it — the revert is itself part of the
record.

If secrets were committed, **rotate them**. Rewriting history does not un-publish what
was already fetched, cloned, cached by CI, or indexed. Treating a rewrite as
remediation is the mistake; the credential is burned the moment it is pushed.

## 3. Governance and generated code

**Governance files escalate.** CI workflows, `CODEOWNERS`, `LICENSE`,
`.claude/settings.json`, `hooks.json`, `.gitattributes`, `knowledge.schema.json`.
These are the layer that enforces everything else — a change here can silently disable
every other control. They are legitimately edited (this repository's own CI was
written by an agent), so the rule is *never unattended*, not *never*.

**Generated code is denied.** Any file whose first 20 lines carry `@generated`,
`DO NOT EDIT`, or `Code generated by` must not be hand-edited by anyone, human or
agent. The next regeneration silently discards the change, so the edit is not merely
wrong — it is invisibly temporary. Edit the generator or its input schema.

## 4. Credentials must never be committed

Rejected in pre-commit and CI: `.env`, `*.pem`, `*.key`, `*.p12`, `id_rsa`,
`id_ed25519`, `*.keystore`, cloud provider keys, JWT secrets, connection strings with
embedded passwords.

GitHub's own secret scanning push protection is **not available on Free private
repositories** (ADR-0004), so this is enforced by `gitleaks` in pre-commit and CI
rather than at the push boundary. That is strictly weaker — it cannot stop a
`--no-verify` push — which is one more reason the plan upgrade in ADR-0004 matters.

## What this does not cover

These guards run inside Claude Code (ADR-0007). A command typed directly into a
terminal is unaffected. The layers that catch that are pre-commit, CI, and
`forge audit` — none of which can block a merge on the current plan. The guards
narrow the window; they do not close it.
